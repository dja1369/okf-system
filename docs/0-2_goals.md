# 남은 벤치마크 작업 — `/goal` 붙여넣기용

각 항목의 코드 블록을 **그대로 복사해 `/goal`에 넣으면** 그 작업이 실행된다.
**전부 Claude Code만으로 처리된다** — Codex나 외부 도구가 필요한 것은 없다.
(Codex 검증은 2026-07-26 시점 워크스페이스 지출 한도 초과로 막혀 있고, 그 역할은
아래 §0의 "적대적 검증" goal이 대체한다.)

**시작 전에 반드시 확인할 것**

- `main`은 브랜치 보호로 잠겨 있다. 직접 push·merge·force-push 금지. 항상 새 브랜치 + PR.
- 라이브 번들 `~/.claude/okf`의 `raw/`·`_remove_candidate/`는 **절대 열지 않는다**(사용자 대화 전사 원문).
- 훅 서브프로세스를 띄우기 전 `okfPaths(home).lock`에 `{pid, startedEpochMs}`를 **선주입**한다.
  빠지면 detached 실배치가 떠서 **실제로 과금된다.**
- 미커밋 상태에서 `git checkout -- <파일>`을 쓰지 않는다(작업이 날아간 전례가 있다). 사본을 떠라.

**현재 상태 (2026-07-26)**

| 축 | 상태 |
|---|---|
| A-1 recall@cap | **E1·E2·E3 발행 완료** ($0) |
| A-2 중첩 깊이 | **완료** (F/N2/N3/N4) |
| A-3 포맷 회귀 | **완료** |
| B 운영 지표 | 표본 20회차 대기 |
| C 유료 축 | v0.3 이후, 조건 3개 충족 시 |
| D 지식 재활용 | **미착수 — 유료, 사용자 승인 필요** |

## 0. 적대적 검증 (아무 작업 뒤에나 붙여 쓴다) — $0

E1에서 이 검증이 **실제 결함 5건**을 잡았다(가드 3종이 전부 "지워도 초록", 헤드라인 원인
오귀인, 픽스처 선행 고정 누락). 발행 전에 반드시 돌린다.

```
방금 한 작업을 적대적으로 검증해줘. 서로 다른 렌즈 3개를 병렬 서브에이전트로 붙인다.

1) 측정 타당성 — "이 결과는 하니스의 인공물이다"를 논증하라. 조건을 바꿔 실제로
   재실행해서 확인하라(주장만 하지 마라).
2) 안전·사양준수·테스트 무결성 — 새로 추가한 단언마다 그것이 지키려는 가드를 실제로
   돌연변이시켜 FAIL하는지 확인하라. 지워도 초록인 단언은 무가치하다. PASS=0은 CRASH,
   총 단언 수가 기준선보다 적으면 SHORT다. 구분해 보고하라. 돌연변이는 적용됐는지
   grep으로 확인하고 반드시 사본으로 복구하라.
3) 발행 문장 검토 — 리포트를 문장 단위로 훑어 "이 문장이 참이려면 무엇이 성립해야
   하는가"를 묻고 원시 데이터로 뒷받침되는지 확인하라. 뒷받침 안 되면 대체 문장을 써라.

제약: 라이브 번들 ~/.claude/okf 접근 금지, claude CLI 호출 금지(과금), 저장소 파일
수정 금지, 확신 없으면 "문제 있음" 쪽으로 기울여라, 칭찬 금지.

나온 지적은 남의 말로 받아들이지 말고 직접 확인한 뒤 반영해줘. 고칠 수 없거나 고치면
발행된 수치가 바뀌는 것은 "안고 가는 결함"으로 리포트에 명시해줘.
```

## 1. ~~E3~~ — **완료** (2026-07-26). 다음은 E4다 ($0)

E3가 닫은 것: 추세 판정 기준 재정의(부호검정 + 중앙값 CI), R3 재정의(R3a/R3b), `rank < taken`
정확 분해, 실사용 title 분포. 리포트는 [`gate-recall-2026-07-26-e3.md`](benchmarks/gate-recall-2026-07-26-e3.md).

**E3가 남긴 것이 E4의 과제다.** 앞 회차와 달리 E4는 **크기를 재는 회차**다 — E1~E3는 전부
"어느 방향인가"까지만 갔다.

```
@docs/benchmarks/gate-recall-2026-07-26-e3.md 를 읽고 E4를 진행해줘. bench/0-2-axis-a 브랜치에서
이어서 작업하고(하니스가 그 브랜치에만 있다), 끝나면 8개 언어 README의 통합 벤치마크 섹션에
반영한 뒤 PR을 갱신해줘.

E4가 닫아야 할 것:
1. **중첩 정렬 지렛대의 크기를 재라.** `# Subdirectories` 섹션이 type 섹션보다 대소문자 구분
   정렬에서 앞서므로(lib/index-gen.mjs:242) 중첩 concept가 카테고리 앞으로 끌어올려진다.
   E1이 5개 요인 중 첫 번째로 이미 문서화했고 E3가 라이브 번들에서 관측했지만(정렬 위반 3건이
   하위 디렉토리 보유 여부와 정확히 일치), **크기는 아무도 재지 않았다.** title 섭동과 같은
   방식으로 순수 검정하라 — 본문·title 고정, 경로 깊이만 조작.
2. **검정력을 먼저 계산하고 시드 수를 정하라.** E3의 flat 판정 다수가 동점 과다로 검정력이
   없다(100→200에서 20개 중 12개가 동점). "차이가 없다"와 "세우지 못했다"를 가르려면 시드가
   몇 개 필요한지를 **측정 전에** 계산해 사전등록하라.
3. **적재율을 실험 변수로 올려라.** E3는 적재율이 E2 결과(정렬이 두 배를 만든다)와 E3 결과
   (실사용에서 아직 안 물린다)를 잇는 매개라고 적었지만 검정하지 않았다. 적재율을 직접
   조작(cap 또는 N)해 정렬 효과가 적재율의 함수인지 확인하라.
4. **실사용 표본 1개 문제.** E3의 title 분포는 저자 한 명의 번들 26개이고 p=0.667이다.
   공개 OKF 번들이나 합성 번들로 표본을 늘릴 수 있는지 조사하고, 못 늘리면 그 사실을
   한계로 발행하라 — 표본을 못 늘린 채 같은 측정을 반복하지 마라.

규율(E2·E3에서 확립됨, 반드시 승계):
- 픽스처를 **사전등록 커밋에 함께** 넣는다. 스모크가 git log --diff-filter=A로
  "픽스처 커밋 < 리포트 커밋"을 엄격 부등호로 강제한다(E3 단언이 이미 있다).
- 사전등록서를 리포트보다 먼저 커밋한다(G3-0f). 산출 JSON의 meta.commit이 사전등록 커밋을
  가리켜야 한다.
- 조건을 바꾸지 않는 회차라면 앞 회차 셀이 **전부 재현되는지**를 회귀 가드로 삼아라.
- 임계는 측정 전에 확정하고, 숫자를 본 뒤에 완화하지 않는다. 문서를 측정 뒤에 썼다면
  그 사실과 그 시점에 이미 알고 있던 값을 전부 공개한다.
- **측정 뒤에 산술을 고쳤다면 그것이 바꾼 판정까지 공개하라**(E3 사전등록서 §9가 선례다).
- E1·E2·E3의 픽스처·리포트·raw는 한 글자도 고치지 않는다. 발행된 기록이다.
- 유료 0은 선언이 아니라 PATH 트랩으로 실행 중에 증명한다.
- 라이브 번들 측정은 읽기 전용이고, 산출물에 title·설명·파일명·링크를 싣지 않는다.

끝나면 @docs/0-2_goals.md 의 적대적 검증 goal을 이어서 돌려줘.
```

## 2. 축 D — 지식 재활용 실측 (**유료, 사용자 승인 필요**)

**이 goal은 돈을 쓴다.** 파일럿 18세션 ≈ $9, 전체 하드 스톱 **$60**.
설계·준비 절차는 [`0-2_benchmark.md`](0-2_benchmark.md) §7에 전부 있다.

**준비 1~6은 전부 $0**이므로, 승인 전에 준비만 먼저 돌려도 된다:

```
@docs/0-2_benchmark.md 의 축 D 준비 단계만 진행해줘. §7-12의 준비 1~6을 순서대로 끝내고,
준비 5(사전등록서 커밋)까지 마친 뒤 **멈춰라**. 유료 호출은 한 건도 내지 마라.

준비 단계는 전부 $0이며, 하나라도 판정 기준을 못 맞추면 그 단계에서 멈추고 무엇이
막혔는지 보고해줘.

컨텍스트 효율: §7-13을 따른다. 준비 1~4를 포함해 시끄러운 일은 전부 서브에이전트로
처리하고, 메인 스레드는 해시·바이트 오차율·통과 여부 같은 한 줄짜리 판정값만 받는다.
서브에이전트 반환에는 반드시 schema를 걸고, 전사·로그·diff는 파일 경로로만 받는다.

제약: 라이브 번들 ~/.claude/okf 에는 절대 쓰지 않는다. raw/ 는 읽지도 복사하지도 않는다.
```

승인 후 본 실행:

```
@docs/0-2_benchmark.md 의 축 D를 실행한다. 비용 상한 $60 하드 스톱을 승인한다.

준비 1~6이 이미 끝나 있으면 그것을 쓰고, 아니면 먼저 끝내라. 사전등록서 커밋 전에는
유료 호출을 시작하지 마라.

실행은 다이나믹 워크플로우로 한다(채굴 -> 문항화 -> 유효성 -> 파일럿 -> 게이트 ->
본실험 -> 채점 -> 적대적 검증). 파일럿에서 무익성 정지 규칙(ON - OFF <= 1문항)에 걸리면
본실험으로 넘어가지 말고 "지지되지 않음"으로 발행하라. harm_rate > 0.30이면 다른 결과와
무관하게 은퇴 정책을 먼저 손봐라.

예산이 모자라면 **표본을 깎지 말고 파일럿 결과만 발행**하라 — 중간에 N을 줄이면
사전등록이 무의미해진다. 산출물에 spent와 untested 두 값이 모두 들어가야 한다.

컨텍스트 효율: §7-13을 따른다.

산출물: docs/bench/okf-reuse-report-<날짜>.md — 버킷별·전체 모집단 기준 결과, harm_rate,
spent, untested, 그리고 반박자가 제거하지 못한 대안 설명 목록.
```

## 6. Codex 검증이 필요해지면

워크스페이스 지출 한도가 풀린 뒤에만 가능하다(2026-07-26 시점 `You hit your spend cap set by
the owner of your workspace`로 거절됨). 한도가 풀렸다면:

```
codex:rescue 서브에이전트로 현재 브랜치의 마지막 커밋들을 회의적 리뷰어 관점에서 검토시켜줘.
사전등록서와 리포트를 먼저 읽게 하고, 각 지적에 file:line 근거와 "이 지적이 맞으면 리포트의
어느 문장이 거짓이 되는가"를 요구해줘. 칭찬은 받지 마라.

Codex가 지출 한도로 거절하면 즉시 멈추고 보고해줘 — 우회하지 마라.
```

한도가 막혀 있으면 **§0의 적대적 검증 goal이 그 역할을 대체한다.** E1에서 실제로 대체
역할을 했고 결함 5건을 잡았다.
