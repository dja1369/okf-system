# OKF E2 — 사전등록서: 정렬 지배 가설 검정 + E1이 남긴 구멍 닫기 ($0)

**선행 회차**: [`gate-recall-2026-07-26-e1.md`](gate-recall-2026-07-26-e1.md) · [`pre-registration-2026-07-26-e1.md`](pre-registration-2026-07-26-e1.md)
**비용**: $0. 유료 LLM 호출 0건. PATH 트랩으로 실행 중에 증명한다.

**이 커밋이 E2의 사전등록이며, E2 픽스처 3개가 이 커밋에 함께 들어 있다.**
그것이 E2의 존재 이유 중 하나다 — §1 참조.

---

## 0. 이 문서가 언제 쓰였는가 (E1과 같은 형식으로 먼저 밝힌다)

- **판정 기준(R6 임계 0.05, R7, 레벨 집합 [24,50,100,200,400], 섭동 3조건)은 구현 착수 전에
  확정해 구현 지시서에 문자 그대로 넣었다.** 숫자를 보고 임계를 정하지 않았다.
- **그러나 이 문서를 쓴 시각은 검증 실행보다 뒤다.** E1과 같은 이유다 — 하니스를 만들어
  돌려보지 않고는 "결정적이다"·"E1 재현이 안 깨졌다"·"돈을 안 쓴다"를 확인할 수 없다.
- **E1보다 나아진 점이 정확히 하나 있다**: E1은 질문 세트·distractor·형상 픽스처가
  **리포트 커밋**에서 처음 git에 등장했다. E2는 그 세 개가 **이 사전등록 커밋**에 들어 있고,
  스모크가 `git log --diff-filter=A`로 "픽스처 커밋 < 리포트 커밋"을 **엄격 부등호**로
  검사한다. E1 파일 세트로 그 단언을 겨누면 위반 3건으로 즉시 FAIL한다(돌연변이 확인).
- 이 문서를 쓰는 시점에 이미 알고 있던 관측값은 §8에 전부 공개한다.

**확정 이후 어떤 임계도 완화하지 않는다.** R3이 또 발화하면 발화로 발행한다.

## 1. E2가 닫으려는 것 — E1 리포트 §6-b가 남긴 목록

| # | E1이 남긴 결함 | E2의 처리 |
|---|---|---|
| 1 | 픽스처가 사전등록이 아니라 리포트 커밋에서 처음 등장 | **이 커밋에 픽스처 동봉 + 스모크가 엄격 부등호로 강제** |
| 2 | filler `title` 중복(N=200 patterns 42개 중 distinct 23, 최대 5중복)이 한 카테고리의 두 슬롯을 같은 title 두 벌로 먹음 | 생성 시 결정적 유일 접미로 **구성적 차단**. R7이 감시 |
| 3 | 동결 index 예산이 라이브보다 11B 작음(`frozenHeadBytes` 686 = 650+36인데 라이브 경로는 25B) | **6,956 → 6,967**로 정정, `frozenHomePathBytes` 25 |
| 4 | R4가 자기 실패 모드("filler 명명에 지배됨")를 원리적으로 탐지 못 함 — 파일명은 효과 0이고 정답 title rank는 시드마다 고정 | **R4 은퇴**, **R6(title 섭동 민감도)로 대체** |
| 5 | R3 발화 원인 가설(평탄화)을 E1에서 검증하지 않고 넘김 | **레벨 400 추가**로 검정 |

E1의 픽스처·리포트·raw는 **한 글자도 고치지 않는다.** 발행된 기록이다.

## 2. 설계

| 항목 | E1 | **E2** |
|---|---|---|
| 레벨 N | 24, 50, 100, 200 | **24, 50, 100, 200, 400** |
| 시드 | 1~20 | 1~20 (동일) |
| 질문 | 20개 | **동일한 20개를 그대로 승계** (바꾸면 E1과 비교 불가) |
| index 예산 | 6,956B / 92줄 | **6,967B** / 92줄 |
| filler title | 절단으로 중복 발생 | **결정적 유일 접미로 중복 0** |
| 섭동 조건 | 없음 | **none / front(`!!! `) / back(`힣힣 `)** |

**섭동은 정답 concept의 frontmatter `title`에만 접두를 붙인다.** 파일명·경로·본문은
한 바이트도 바꾸지 않는다. 그래야 "슬롯을 정하는 것이 정렬인가"의 순수 검정이 된다.
filler와 부트스트랩 시드는 섭동하지 않는다.

셀 수: 3조건 × 5레벨 × 20시드 = **300샘플**.

---

## 3. 검정하려는 가설

**H1 (정렬 지배)**: 게이트가 어느 concept를 싣는지는 관련성이 아니라 생성 시점의 정렬이 정한다.
→ 그렇다면 **`title`만 바꿔도 recall이 크게 움직여야 한다.**

**H2 (평탄화)**: E1의 R3 발화는 recall이 바닥에 붙어 평탄해지기 때문이다.
→ 그렇다면 **N=400에서도 N=200과 거의 같아야 한다.**

H1은 E1 §4가 세운 진단이고, H2는 E1 §6-3이 "이번 회차에서 검증하지 않는다"며 넘긴 가설이다.
**둘 다 E2가 반증 가능한 형태로 검정한다.**

## 4. 예측

| # | 예측 |
|---|---|
| **P1** | 섭동 3조건의 recall 차이(spread)가 **모든 레벨에서 0.10 이상**이다 (H1이 참이면) |
| **P2** | `front` 조건의 recall이 `none`보다 **높고**, `back`은 **낮다** (정렬 앞으로 끌면 살아남는다) |
| **P3** | `recall(400)`이 `recall(200)`과 **0.05 이내**다 (H2 평탄화가 참이면) |
| **P4** | `recall(24) ≥ 0.400` — 예산이 11B 커졌으므로 E1보다 줄지 않는다 |
| **P5** | 모든 샘플에서 filler title `maxDuplicate === 1` |
| **P6** | 카테고리당 `taken`이 1~3 범위를 유지한다 |

## 5. 반증 기준 — 코드가 JSON에 boolean으로 찍는다

**R1·R2·R3·R5는 E1과 동일한 문언·임계를 쓴다**(계획서 `ba961c5` 원문). R4는 은퇴하고
R6·R7을 새로 둔다.

| # | 발화 조건 | 발화 시 결론 |
|---|---|---|
| **R1** | `recall(50) ≥ 0.90` | 라우팅은 병목이 아니다 → I2를 v0.3에서도 착수하지 않는다 |
| **R2** | `recall(24) < 0.60` | 실사용 규모에서 이미 실패 중 |
| **R3** | 레벨에 따른 단조 감소 위반 | 하니스 결함 — 전 결과 폐기 |
| **R4** | **은퇴** | 시드 분산은 정답 title rank가 시드마다 고정이라 이 실패 모드를 탐지할 수 없다. R6이 대체한다. 값은 기록만 하고 판정에 쓰지 않는다 |
| **R5** | 캘리브레이션 값 불일치 (E2 재측정값 기준) | 전 결과 무효 |
| **R6** | 섭동 3조건의 recall spread가 **모든 레벨에서 0.05 미만** | **H1 반증** — "슬롯을 title 정렬이 정한다"는 E1 진단이 틀렸다. E1 §4를 철회해야 한다 |
| **R7** | 어느 샘플에서든 filler title `maxDuplicate > 1` | 하니스 결함 — 전 결과 폐기 |

### R3에 대한 처리 규칙 — E1과 동일하게 유지한다

E1에서 R3이 발화했고, 그 처리 규칙(§6)을 **완화하지 않고 그대로 승계**한다:
발화하면 발화로 발행하고, **recall 절대값을 정책 근거로 쓰지 않는다.** 원인 가설은
그 회차에서 검증하지 않는다.

**단, E2는 H2(평탄화)를 명시적 검정 대상으로 사전등록했으므로**, P3의 판정은
"사후 변명"이 아니라 등록된 검정이다. P3이 반증되면 **평탄화 설명은 폐기**하고,
그 자리에 새 설명을 끼워 넣지 않는다 — 다음 회차의 별도 사전등록 대상이다.

## 6. E1과 달라진 값은 결과를 어떻게 바꾸는가 (미리 적는다)

E2는 예산(+11B)과 filler 생성(유일 접미)을 바꿨으므로 **E1과 숫자가 같을 이유가 없다.**
따라서 E2의 recall을 E1과 직접 비교해 "개선/악화"라고 말하지 않는다. 두 회차는 **다른 조건**이다.
비교 가능한 것은 **E2 안의 세 섭동 조건끼리**이며, 그것이 H1 검정의 전부다.

---

## 7. 알려진 한계 (결과를 보기 전에 적는다)

1. **섭동 접두는 인위적이다.** 실제 concept의 title이 `!!! `로 시작하지는 않는다. 이 실험이
   보이는 것은 "정렬 위치가 생존을 정한다"까지이고, **실사용에서 title이 얼마나 다양한지는
   재지 않는다.**
2. **`힣힣 `(back)은 한글 정렬 꼬리를 이용한다.** UTF-8 코드포인트 순서에 의존하므로
   로케일 정렬을 쓰는 다른 구현에서는 재현되지 않을 수 있다.
3. **recall은 여전히 정답률이 아니다.** E1 §0을 그대로 승계한다.
4. **합성 distractor는 상한만 준다.** filler 중복을 없앤 것은 E1보다 **더 엄격**해진 것이지
   실번들에 가까워진 것이 아니다.
5. **질문 20개는 E1과 동일하다.** 문항 선택의 편향은 E1과 똑같이 남아 있다.
   특히 `cwdIndependent` 6개가 곧 직접 작성한 6개라는 교란도 그대로다.
6. **N=400은 실사용 규모를 넘는다.** 라이브 번들은 22개다. 400은 곡선의 형태를 보려는
   외삽점이지 실사용 예측이 아니다.

## 8. 이 문서를 쓰는 시점에 이미 알고 있던 것 (전면 공개)

구현 검증 실행에서 관측된 값이다. **이 값을 본 뒤에 §4·§5의 어떤 숫자도 바꾸지 않았다.**

| N | none | front | back | spread |
|---|---|---|---|---|
| 24 | 0.4000 | 1.0000 | 0.4000 | 0.6000 |
| 50 | 0.2775 | 0.5600 | 0.1825 | 0.3775 |
| 100 | 0.2475 | 0.5225 | 0.1700 | 0.3525 |
| 200 | 0.2500 | 0.5275 | 0.1750 | 0.3525 |
| 400 | 0.2625 | 0.5325 | 0.1850 | 0.3475 |

- **R6 미발화** → H1(정렬 지배) 반증되지 않음. spread가 임계의 7~12배다.
- **P3 반증 예상** → `recall(400)` − `recall(200)` = +0.0125로 0.05 이내지만, 방향이
  평탄이 아니라 **상승**이고 R3 위반이 200→400에 새로 생겼다. 판정은 리포트에서 확정한다.
- R7 미발화(300샘플 전부 `maxDuplicate === 1`), R5 미발화(8개 값 오차 0),
  R2 발화, R3 세 조건 모두 발화.
- E1 재현 불변 확인: E2 확장 후에도 E1 경로가 `0.4000 / 0.2775 / 0.2450 / 0.2475`를 그대로 낸다.

**리포트는 이 커밋 이후 재실행해 발행한다.** 산출 JSON의 `meta.commit`이 이 커밋을 가리켜야 한다.
