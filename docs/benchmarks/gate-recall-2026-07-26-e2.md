## 0. 먼저 — 이 숫자로 하면 안 되는 말

> **recall은 정답률이 아니다.** 합성 distractor는 라우터 성능의 **상한만** 준다.
> **E2의 숫자를 E1과 직접 비교해 "개선/악화"라고 말하면 안 된다** — 예산(+11B)과 filler
> 생성 방식이 달라졌으므로 두 회차는 다른 조건이다. 비교 가능한 것은 **E2 안의 세 섭동
> 조건끼리**다.

그리고 **R3이 또 발화했다.** 사전등록한 처리 규칙을 그대로 승계해 **recall 절대값을 정책
근거로 쓰지 않는다.**

## 1. 결과 — 섭동 3조건 × 5레벨

`title` 앞에 4글자를 붙인 것 외에 **파일명·경로·본문은 한 바이트도 바뀌지 않았다.**

| N | none | front (`!!! `) | back (`힣힣 `) | **spread** |
|---|---|---|---|---|
| 24 | 0.400 ± 0.000 (n=20, 0.40–0.40) | **1.000 ± 0.000** (n=20, 1.00–1.00) | 0.400 ± 0.000 (n=20, 0.40–0.40) | **0.600** |
| 50 | 0.277 ± 0.038 (n=20, 0.20–0.35) | 0.560 ± 0.064 (n=20, 0.50–0.70) | 0.182 ± 0.044 (n=20, 0.15–0.30) | **0.378** |
| 100 | 0.247 ± 0.034 (n=20, 0.20–0.30) | 0.523 ± 0.030 (n=20, 0.45–0.55) | 0.170 ± 0.025 (n=20, 0.15–0.20) | **0.353** |
| 200 | 0.250 ± 0.040 (n=20, 0.15–0.30) | 0.528 ± 0.030 (n=20, 0.45–0.55) | 0.175 ± 0.026 (n=20, 0.15–0.20) | **0.353** |
| 400 | 0.262 ± 0.039 (n=20, 0.15–0.30) | 0.533 ± 0.024 (n=20, 0.50–0.55) | 0.185 ± 0.024 (n=20, 0.15–0.20) | **0.348** |

**N=400에서 `title` 4글자로 recall이 0.262 → 0.533으로 두 배가 된다. N=24에서는 1.000이다.**
같은 지식, 같은 파일, 같은 번들 크기다. 바뀐 것은 정렬 위치뿐이다.

### `cwdIndependent` 부분집합 — E1의 P5 반증이 무엇이었는지 확정된다

| N | none | front | back |
|---|---|---|---|
| 24 | 0.500 | **1.000** | 0.500 |
| 100 | 0.017 | **0.958** | 0.000 |
| 200 | 0.000 | **0.967** | 0.000 |
| 400 | 0.000 | **0.967** | 0.000 |

E1에서 이 부분집합은 N≥200에서 **전멸(0.000)**했고, 그것이 P5 반증의 내용이었다.
E1 리포트는 그것을 "효과가 아니라 픽스처 인공물"로 읽었다(계획서가 미리 규정한 대로).
**E2가 그 해석을 실측으로 확정한다** — `title`에 접두 4글자를 붙이자 같은 6개가
**0.000 → 0.967**로 올라온다. 이 concept들이 안 실렸던 이유는 저장소 독립적이어서가 아니라
**정렬에서 뒤에 있었기 때문**이다.

## 3. 예측 P1 ~ P6 대조

| # | 예측 | 결과 | 판정 |
|---|---|---|---|
| **P1** | spread가 모든 레벨에서 ≥ 0.10 | 0.348 ~ 0.600 | **지지** |
| **P2** | front > none > back | 5개 레벨 전부에서 성립 (N=24만 back = none, 아래 참조) | **지지** |
| **P3** | `\|recall(400) − recall(200)\|` ≤ 0.05 (평탄화) | none +0.0125 · front +0.005 · back +0.010 | **형식상 지지** — 아래 단서 |
| **P4** | `recall(24) ≥ 0.400` | 0.400 | **지지** (동률) |
| **P5** | 모든 샘플 `maxDuplicate === 1` | 300/300 | **지지** |
| **P6** | 카테고리당 `taken` 1~3 유지 | 유지 | **지지** |

### P3에 붙는 단서 — 내 조작적 정의가 약했다

P3은 "0.05 이내"로 등록했고 실측 +0.0125는 그 안에 든다. **그러나 세 조건 모두에서
N=100 → 200 → 400이 단조로 오른다**(none 0.247 → 0.250 → 0.262). 이건 "바닥에 붙어
평탄"이 아니라 **완만한 상승**이고, R3이 200→400에서 **새로 위반**을 낸 이유이기도 하다.

즉 **`|Δ| ≤ 0.05`라는 조작적 정의는 "평탄"과 "천천히 상승"을 구별하지 못한다.** 내가 등록한
기준의 결함이다. 등록한 대로 P3을 지지로 판정하되, **H2(평탄화)가 서술로서 확인됐다고는
쓰지 않는다.** 상승의 원인은 이번 회차에서 설명하지 않는다 — 사전등록 §5가 "그 자리에 새
설명을 끼워 넣지 않는다"고 미리 못박았다. 다음 회차의 별도 사전등록 대상이다.

### P2에 붙는 단서 — N=24에서 back = none인 이유

N=24는 정답 20 + 부트스트랩 시드 4라 **filler가 0개**다. 경쟁자가 없으면 뒤로 밀 상대도
없으므로 `back` 접두가 효과를 내지 못한다. 반대로 `front`는 시드 4개를 밀어내고 1.000을 만든다.
설계상 필연이며 결함이 아니다.

## 4. 캘리브레이션 (G3-0a) — E1의 11B 오차가 해소됐다

E1은 `frozenHeadBytes: 686` = 650(head 상수) + 36(경로)을 썼는데, 기본 라이브 경로
`~/.claude/okf`는 **25B**다. E2는 이를 정정했다.

| 값 | E1 | **E2** | 차이 |
|---|---|---|---|
| `frozenHomePathBytes` | 36 | **25** | −11 |
| `frozenHeadBytes` | 686 | **675** | −11 |
| `indexBudgetBytes` | 6,956 | **6,967** | **+11** |
| taken / total | 12 / 22 | 12 / 22 | 0 |
| indexBytes | 6,834 | 6,834 | 0 |
| assembledBytes | 8,879 | 8,868 | −11 |
| leftoverBytes | 114 | **125** | +11 |
| truncatedBytes / cappedLines | 0 / 0 | 0 / 0 | 0 |

예산이 11B 늘었지만 **다음 줄이 최소 126B라 들어가지 못했고**, 11B가 통째로 leftover에 남았다.
그래서 `taken`은 그대로다. **8개 값 오차 0 → R5 미발화.**

head 경로제외 상수가 정확히 **650B**임은 길이가 다른 두 홈으로 회귀해 실측했다(기울기 1).

**뒤에** 결정적 유일 접미를 붙여 구성적으로 차단했다.

## 6. 이 회차가 답하지 못하는 것

1. **섭동 접두는 인위적이다.** `!!! `로 시작하는 실제 concept는 없다. 이 실험이 보이는 것은
   "정렬 위치가 생존을 정한다"까지이고, 실사용 title 분포가 얼마나 치우쳐 있는지는 재지 않았다.
2. **`힣힣 `는 UTF-8 코드포인트 순서에 의존한다.** 로케일 정렬을 쓰는 구현에서는 재현되지
   않을 수 있다.
3. **N=400은 실사용 규모를 넘는다.** 라이브 번들은 22개다. 곡선 형태를 보려는 외삽점이다.
4. **질문 20개는 E1과 동일**하므로 문항 선택 편향도 그대로다.
5. **상승의 원인**을 설명하지 않는다. 사전등록이 금지했다.
6. **recall이 정답률로 전이되는지**는 여전히 유료 축(P-A)의 영역이다.

## 8. 결론

1. **`title` 정렬이 게이트 생존을 지배한다는 진단은 반증 시도를 견뎠다.** 본문·파일명·경로를
   고정한 채 `title` 앞 4글자만으로 recall이 N=400에서 0.262 ↔ 0.533, N=24에서 0.400 ↔ 1.000으로
   갈린다. **관련성 신호가 0건인 시스템에서 이것은 예상되는 결과이지 버그의 발견이 아니다** —
   다만 그 크기가 처음으로 숫자로 나왔다.
2. **E1의 P5 반증은 "저장소 독립적 지식이 불리하다"가 아니었다.** 같은 6개가 접두 하나로
   0.000 → 0.967이 된다. 명명의 함수였다.
3. **R2·R3은 또 발화했고, recall 절대값은 여전히 정책 근거가 아니다.** 이 회차도 I2 착수 여부를
   결정하지 않는다.
4. **측정 규율 쪽에서는 진짜로 한 칸 나아갔다.** 픽스처가 사전등록 커밋에 들어갔고, 그것을
   기계가 강제하며, 그 강제가 E1의 실제 사고를 잡는다는 것까지 확인했다.

**결과가 예측과 달라도 서술을 바꾸지 않았다.** P3의 조작적 정의가 약했다는 것도 그대로 적는다.
